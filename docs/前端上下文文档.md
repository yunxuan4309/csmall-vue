## 一、项目概述

**项目名称**: csmall-vue
**类型**: 微服务电商平台前端（CoolShark 商城）
**技术栈**: Vue 3.5 + Vite 7 + Element Plus 2.13 + Pinia 3 + Vue Router 4
**当前状态**: 本地开发环境（已从生产环境回退）

**后端架构**: Spring Cloud Alibaba 微服务（Gateway 10087 统一入口）

| 服务 | 端口 | 说明 |
|------|------|------|
| Gateway | 10087 | API 网关，前端所有请求统一入口 |
| SSO | 10009 | 登录认证 |
| Product | 9010 | 商品管理（内部 Dubbo，不直接暴露） |
| Front | 10004 | 前台商品展示 |
| Order | 10005 | 订单/购物车 |
| Seckill | 10007 | 秒杀 |
| UMS | 10006 | 用户管理 |
| AMS | 10003 | 后台管理 |
| Resource | 9060 | 文件上传 |
| AI | 10010 | 智能导购 |

## 二、开发环境配置

### 2.1 环境变量

**.env**（通用配置）:
```
VITE_TOKEN_KEY=mall_token
VITE_TOKEN_PREFIX=Bearer
VITE_TOKEN_EXPIRATION=604800
```

**.env.development**（开发环境）:
```
VITE_API_SSO=http://localhost:5173
VITE_API_GATEWAY=http://localhost:5173
VITE_API_UMS=http://localhost:5173
VITE_API_FRONT=http://localhost:5173
VITE_API_SECKILL=http://localhost:5173
```

> 开发环境所有 API 地址统一指向 `localhost:5173`（Vite dev server），通过 Vite 代理转发到 Gateway (10087)。

### 2.2 Vite 代理配置

`vite.config.js` 中将所有服务路径代理到 Gateway：

```js
server: {
  proxy: {
    '/sso':    'http://localhost:10087',
    '/front':  'http://localhost:10087',
    '/oms':    'http://localhost:10087',
    '/search': 'http://localhost:10087',
    '/resource':'http://localhost:10087',
    '/seckill':'http://localhost:10087',
    '/admin':  'http://localhost:10087',
    '/user':   'http://localhost:10087',
    '/ums':    'http://localhost:10087',
    '/ai':     'http://localhost:10087',
  }
}
```

### 2.3 启动命令

```bash
npm install
npm run dev      # 开发服务器 → http://localhost:5173
npm run build    # 生产构建 → dist/
npm run preview  # 预览生产构建
```

## 四、API 请求架构

### 4.1 Axios 实例

`src/api/request.js` 通过工厂函数 `createInstance(baseURL)` 创建 5 个独立实例：

| 实例 | 用途 | 环境变量 |
|------|------|----------|
| `ssoHttp` | SSO 登录 | `VITE_API_SSO` |
| `gatewayHttp` | 通用业务（推荐走网关） | `VITE_API_GATEWAY` |
| `umsHttp` | 用户管理 | `VITE_API_UMS` |
| `frontHttp` | 前台商品 | `VITE_API_FRONT` |
| `seckillHttp` | 秒杀 | `VITE_API_SECKILL` |

### 4.2 拦截器行为

- **请求拦截**: 自动从 `localStorage` 读取 `mall_token`（或 `admin_token`），添加 `Authorization: Bearer xxx` 头
- **响应拦截**: 统一处理 `state` 码 — `200` 成功返回 data；`401` 清除 Token 跳转登录页；其他弹出错误提示

### 4.3 后端响应格式

```json
{
  "state": 200,
  "message": null,
  "data": { ... }
}
```

| state | 含义 | 前端行为 |
|-------|------|----------|
| 200 | 成功 | 返回 `res.data` |
| 401 | Token 过期/无效 | 清除 Token，跳转登录页 |
| 400/403/404/409/500 | 业务错误 | `ElMessage.error` 提示 |

### 4.4 分页响应格式

```json
{
  "state": 200,
  "data": {
    "page": 1, "pageSize": 10, "total": 58, "totalPage": 6,
    "list": [ ... ]   // 注意：某些服务可能用 "records"
  }
}
```

## 六、路由设计

**模式**: `createWebHistory`（History 模式，需 Nginx `try_files` 回退）

**路由守卫**:
- 未登录访问需认证页面 → 跳转登录页
- 已登录访问登录页 → 跳转首页
- 管理员路由 `/admin/*` 使用 admin 布局 + 额外权限校验
- 前台路由 `/` 使用 front 布局

## 七、关键开发注意事项

1. **API 响应格式**: 后端统一返回 `{ state: 200, message: null, data: {...} }`
2. **分页字段不统一**: 不同服务可能用 `list` 或 `records`，注意兼容
3. **Token 存储**: `localStorage.getItem('mall_token')`，管理后台用 `admin_token`
4. **History 模式**: 路由使用 `createWebHistory`，生产 Nginx 需 `try_files $uri $uri/ /index.html`
5. **空字符串问题**: 可选字段传 `""` 可能触发后端 `@NotEmpty` 校验，应传 `null` 或不传
6. **Element Plus 2.13**: `label` 属性已弃用，`el-option` 等组件改用 `value`
7. **Long 精度**: 后端雪花 ID 为 19 位数字，JS Number 会丢失精度。后端已全局序列化 `Long → String`，前端按字符串处理 ID
8. **路径别名**: `@` 映射到 `src/`，import 时用 `@/api/xxx`、`@/components/xxx`
9. **代码风格**: 统一 `<script setup>` + Composition API，文件命名 kebab-case，组件命名 PascalCase
10. **.env.production 问题**: 当前 `.env.production` 只定义 `VITE_API_BASE_URL=/api`，与代码中 5 个独立变量不匹配，需要统一
