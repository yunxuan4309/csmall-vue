## 一、项目概述

**项目名称**: csmall-vue
**类型**: 微服务电商平台前端（CoolShark 商城）
**技术栈**: Vue 3.5 + Vite 7 + Element Plus 2.13 + Pinia 3 + Vue Router 4
**当前状态**: 本地开发环境（已从生产环境回退）

**后端架构**: Spring Cloud Alibaba 微服务（Gateway 10087 统一入口）

| 服务 | 端口 | 说明 |
|------|------|------|
| Gateway | 10087 | API 网关，前端所有请求统一入口 |
| SSO | 10009 | 登录认证 |
| Product | 9010 | 商品管理（内部 Dubbo，不直接暴露） |
| Front | 10004 | 前台商品展示 |
| Order | 10005 | 订单/购物车 |
| Seckill | 10007 | 秒杀 |
| UMS | 10006 | 用户管理 |
| AMS | 10003 | 后台管理 |
| Resource | 9060 | 文件上传 |
| AI | 10010 | 智能导购 |

## 四、API 请求架构

### 4.1 Axios 实例

`src/api/request.js` 通过工厂函数 `createInstance(baseURL)` 创建 5 个独立实例：

| 实例 | 用途 | 环境变量 |
|------|------|----------|
| `ssoHttp` | SSO 登录 | `VITE_API_SSO` |
| `gatewayHttp` | 通用业务（推荐走网关） | `VITE_API_GATEWAY` |
| `umsHttp` | 用户管理 | `VITE_API_UMS` |
| `frontHttp` | 前台商品 | `VITE_API_FRONT` |
| `seckillHttp` | 秒杀 | `VITE_API_SECKILL` |

### 4.2 拦截器行为

- **请求拦截**: 自动从 `localStorage` 读取 `mall_token`（或 `admin_token`），添加 `Authorization: Bearer xxx` 头
- **响应拦截**: 统一处理 `state` 码 — `200` 成功返回 data；`401` 清除 Token 跳转登录页；其他弹出错误提示

### 4.3 后端响应格式

```json
{
  "state": 200,
  "message": null,
  "data": { ... }
}
```

| state | 含义 | 前端行为 |
|-------|------|----------|
| 200 | 成功 | 返回 `res.data` |
| 401 | Token 过期/无效 | 清除 Token，跳转登录页 |
| 400/403/404/409/500 | 业务错误 | `ElMessage.error` 提示 |

### 4.4 分页响应格式

```json
{
  "state": 200,
  "data": {
    "page": 1, "pageSize": 10, "total": 58, "totalPage": 6,
    "list": [ ... ]   // 注意：某些服务可能用 "records"
  }
}
```

## 六、路由设计

**模式**: `createWebHistory`（History 模式，需 Nginx `try_files` 回退）

**路由结构**:
- `/products` — 前台商品列表
- `/product/:id` — 商品详情
- `/cart` — 购物车（需登录）
- `/order/settle` — 确认订单（需登录）
- `/order/list` — 我的订单（需登录）
- `/order/detail` — 订单详情（需登录）
- `/order/pay` — 订单支付（需登录）
- `/pay-result` — 支付结果回调页（无需登录，供支付宝/微信回调）
- `/seckill` — 秒杀专区
- `/seckill/:id` — 秒杀详情
- `/ai` — AI 智能导购（需登录）
- `/user/profile` — 个人中心（需登录）
- `/login` — 统一登录入口
- `/user/login` — 用户登录
- `/register` — 用户注册
- `/admin/login` — 管理员登录
- `/admin/dashboard` — 后台仪表盘
- `/admin/*` — 后台管理各模块

**路由守卫**:
- 未登录访问需认证页面 → 跳转登录页
- 已登录访问登录页 → 跳转首页
- 管理员路由 `/admin/*` 使用 admin 布局 + 额外权限校验
- 前台路由 `/` 使用 front 布局
- `/:pathMatch(.*)*` 通配符重定向到 `/`

## 七、关键开发注意事项

1. **API 响应格式**: 后端统一返回 `{ state: 200, message: null, data: {...} }`
2. **分页字段不统一**: 不同服务可能用 `list` 或 `records`，注意兼容
3. **Token 存储**: `localStorage.getItem('mall_token')`，管理后台用 `admin_token`
4. **History 模式**: 路由使用 `createWebHistory`，生产 Nginx 需 `try_files $uri $uri/ /index.html`
5. **空字符串问题**: 可选字段传 `""` 可能触发后端 `@NotEmpty` 校验，应传 `null` 或不传
6. **Element Plus 2.13**: `label` 属性已弃用，`el-option` 等组件改用 `value`；`ElRadio` 的 `label` 改用 `value`
7. **Long 精度**: 后端雪花 ID 为 19 位数字，JS Number 会丢失精度。后端已全局序列化 `Long → String`，前端按字符串处理 ID
8. **路径别名**: `@` 映射到 `src/`，import 时用 `@/api/xxx`、`@/components/xxx`
9. **代码风格**: 统一 `<script setup>` + Composition API，文件命名 kebab-case，组件命名 PascalCase

## 八、生产环境部署（简要）

> 详见后端 `项目上下文文档.md` 附录 A。

部署方式: `npm run build` → 上传 `dist/` 到 Nginx 服务器（`/data/frontend/`）

```bash
# 本地构建
npm run build

# 上传到服务器
scp -r .\dist\* ecs-user@8.156.85.160:/data/frontend/

# Nginx 重载
sudo nginx -s reload
```

Nginx 核心配置: `location /` 走 SPA 回退，各路径前缀（`/front/`、`/sso/`、`/oms/`、`/search/`、`/resource/`、`/seckill/`、`/admin/`、`/user/`、`/ai/`）反向代理到 Gateway（10087）。
