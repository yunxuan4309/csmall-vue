# SPA 刷新 404 与管理员 401 问题排查记录

> 日期：2026-07-26
> 涉及：Vite 7 + Vue Router 4（History 模式）+ 前后端分离代理

---

## 问题一：刷新页面 404

### 现象

管理员后台页（如 `/admin/dashboard`、`/admin/product/spu`）刷新时报 404 `Not Found`。

### 根因

Vite 7 的代理（`server.proxy`）优先级高于 SPA fallback。浏览器刷新时发送带 `Accept: text/html` 的 GET 请求，被代理拦截后转发给后端 Gateway，后端无法处理这个非 API 路径 → 返回 404。Vue Router 从未收到请求，无法接管路由。

### 错误尝试

| 尝试 | 结果 |
|------|------|
| `historyApiFallback: true` | 无效，代理先于 fallback 执行 |
| `bypass` 返回 `false` | 无效，Vite 7 的 http-proxy-middleware 不认 `false` |
| `configureServer` 自建中间件 | 过于激进，拦截了 API 请求导致 401 |

### 最终方案

`bypass` 函数返回 **重定向字符串** `'/index.html'`：

```javascript
// vite.config.js
function spaBypass(req) {
  const accept = req.headers.accept || ''
  if (accept.includes('text/html')) return '/index.html'
}

export default defineConfig({
  server: {
    proxy: {
      '/admin': { target: 'http://localhost:10087', bypass: spaBypass },
      '/sso':   { target: 'http://localhost:10087', bypass: spaBypass },
      // ... 所有代理路由统一加 bypass
    }
  }
})
```

**原理**：浏览器页面请求（`Accept: text/html`）→ bypass 返回 `'/index.html'` → Vite 返回 SPA 入口 → Vue Router 接管路由。API 请求（`Accept: application/json, */*`）→ bypass 返回 `undefined` → 正常代理到后端。

## 问题二：管理员刷新后 401

### 现象

管理员登录成功，刷新页面后 API 请求返回 `{"state":401,"message":"您没有登录！"}`。

### 根因

Axios 请求拦截器优先使用 `mall_token`（普通用户），管理员路径 `/admin/**` 的请求也用了这个顺序：

```javascript
// 原代码 - 错误
let token = localStorage.getItem('mall_token')
if (!token) {
  token = localStorage.getItem('admin_token')
}
```

此时如果存在过期的 `mall_token`（之前登录过普通用户未登出），拦截器会优先使用它，后端 SSO 解析到过期 JWT → 401。

### 修复

区分路径来源，管理端路径优先 `admin_token`：

```javascript
// 修复后
const adminToken = localStorage.getItem('admin_token')
const mallToken = localStorage.getItem('mall_token')
const isAdminPath = config.url && (config.url.startsWith('/admin') || config.url.startsWith('/pms'))
const token = isAdminPath
  ? (adminToken || mallToken)
  : (mallToken || adminToken)
```

| `src/api/request.js` | 拦截器按路径区分 admin/mall token 优先级 |

---

## 经验总结

1. **Vite 代理 + SPA**：`historyApiFallback` 在代理模式下不生效，必须用 `bypass` 返回重定向字符串
2. **Admin + User 双 Token**：不能简单用同一个优先级，必须按请求路径区分
3. **调试 401**：先开 DevTools Console 看拦截器是否附着 token，再查后端日志看 JWT 解析是否成功
